## MVP Definition

### One-Sentence Definition

The MVP is a **web-based, feed-driven job discovery and application platform** that allows students and young job seekers to quickly browse verified job offers and apply in under 30 seconds using a pre-saved profile.

---

## Main User Flow

1. User opens the web application on the feed page
2. User scrolls through a continuous feed of relevant, verified job offers
3. User selects an offer and views a short, clear summary
4. User clicks **“Instant Apply”**
5. Application is sent using a previously saved CV and cover letter
6. User returns to the feed and continues browsing

This flow is designed to be completed in **short sessions (5–10 minutes)**.

---

## Essential Screens

The MVP includes only the following screens:

* Job offers feed (home)
* Job offer detail / expanded view
* Instant Apply confirmation screen
* Basic profile / saved CV screen (minimal)

No additional navigation layers are required for the core flow.

---

## Minimal Feature Set

The MVP supports:

* Continuous scrolling feed (TikTok / Twitter-style)
* Display of verified job offers
* Clear job summaries (location, hours, salary )
* Instant Apply using a saved CV and cover letter
* Transparent indication of why an offer appears in the feed
* Private messaging between users and recruiters
---

## Explicit Exclusions

The following features are **intentionally excluded** from the MVP:

* Comments or discussion threads
* Advanced recommendation algorithms
* Application tracking dashboards
* Recruiter-side interfaces
* In-app interviews or chat
* Mobile native applications

These exclusions allow the team to focus on validating the **core value proposition**:
**fast, reliable, and non-intimidating job discovery and application**.

---

## Phase 2 Boundary

Only the features described in this document will be implemented during the MVP Development phase.
Any additional functionality will be considered **out of scope** unless explicitly re-prioritized.
